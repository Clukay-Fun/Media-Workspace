# 编排说明（给 AI）

本文件写给**操作工作台、编排口播视频**的 AI（通过 MCP 或 `mw` 命令）。
写代码的规范在 `AGENTS.md`，和本文件是两回事。

字段和操作的准确定义以 `mw guide`（MCP `guide`）返回的 JSON Schema 为准，本文件只讲流程和取舍。

## 1. 基本约定

- 工程是一个 `.mwproj` 目录。**只能通过 `apply`（一批 ops）修改**，不要直接写 `project.json`。
- 每次 `apply` 前先 `inspect` 拿到 `revision`，作为 `baseRevision` 提交；返回 `CONFLICT` 说明人在审片台上改过，重新 `inspect` 再提交。
- 一批 ops 要么全部生效，要么全部不生效。锁定的轨道返回 `TRACK_LOCKED`，不要去解锁，问人。
- 时间一律是整数毫秒。字幕绑定素材的源时间；叠加层优先锚到字幕：`at: { caption: <ID> }`，
  说到某个词时出现用 `at: { caption: <ID>, char: <第几个字> }`，不要自己估算毫秒。
- 原始素材只读。改错了可以 `history` 看版本、`revert` 回退（回退本身也是新的一版）。

## 2. 一条口播的标准流程

1. **导入**：`import` 视频，看返回的 `subtitleCheck` 图——原片已经烧了字幕的话，新字幕会重影，先告诉人。
2. **字幕**：`caption.import` 导入 SRT，然后**先跑 `align` 再剪**：align 会把字幕的开始时间挪到真正开口的地方，
   之后删句才不会把下一句的第一个字剪掉。改了字幕文字要重新 `align`。
3. **粗剪**：
   - 口误、重复的句子：`cut.removeCaptions`（画面和字幕一起剪掉）；
   - 句间停顿：`cut.removePauses`（默认空隙 ≥ 400ms 才剪，两边各留 120ms）；
   - 合并、拆分字幕：`caption.merge` / `caption.split`；
   - 每处剪辑在主轨片段的 `cutBefore` 写上剪掉了什么（16 字以内），审片台会标在时间线上。
   - 剪错了：`uncut`（CLI `mw uncut <工程> <片段>`）把这个片段前面剪掉的画面接回来，
     随删句一起删掉的字幕从历史里找回（逐字时间、高亮都在）。人在审片台点「恢复这一刀」是同一个操作。
4. **章节**：`chapters.set`，每章锚到开头那句字幕，标题 12 字以内。
5. **样式**：先 `styles`（list）看模板库，合适的用 `use` 复制进工程，再在字幕轨道或条目上引用。
   需要微调时用 `style.update`，不要为了一点差别新建样式。
6. **标题、卡片、强调**：**先列方案给人确认，再 apply**（见第 3 节）。
7. **片尾**：人说「接上默认片尾」时调 `outro`（CLI `mw outro <工程>`），不给文件就用默认片尾，默认叠化 300ms；
   没设置过会报 `NOT_FOUND`，请人用 `mw outro-default <视频文件>` 设一个。人给了具体文件就把文件传进去。
8. **自查**（见第 4 节），然后告诉人可以在审片台看了。
9. **处理批注**：见第 5 节。
10. 人说可以了再 `export`；需要封面时 `cover`（见第 8 节）。

## 3. 先列方案，再动手

加标题、卡片、关键词强调、改样式这类「有审美判断」的改动，先列一张表给人看：

| 哪句话 | 加什么 | 用哪个模板 / 样式 | 时间（锚点） |
|---|---|---|---|
| c12「三个方法」 | 顶部标题「三个方法」 | title-bar / title-bar-yellow | 锚到 c12，到 c20 结束 |
| c15「最重要」 | 关键词高亮 + 下划线 | 当前字幕样式的 highlight | c15 的 highlights |

人确认（或改了）之后再一次性 `apply`。纯机械的改动（删口误、去停顿、修错字）不用先问。

## 4. 提交后自查：只修一轮

1. `validate`：有错误必须修。
2. `lint`：字太小、出安全区、字幕放不下、互相遮挡、挡脸。警告逐条看，能修就修，不修的跟人说明原因。
3. `preview --sheet`：均匀截 12 帧看整体；改了某个元素就 `preview --at <条目ID>` 看那一帧。
   要看平台安全区加 `--safe-area douyin`（或 `channels` / `xiaohongshu` / `all`）。
4. 发现问题**只修一轮**，修完把结果交给人，不要反复自己改自己。
5. 修的时候**不改已经确定的时长**：剪辑点、字幕时间、人确认过的标题出现时间都不动，只调样式、位置、文字。

## 5. 处理审片台的批注

- 开始工作前先 `comments`：人在审片台上留的批注带时间点和条目 ID。
- 逐条处理，处理完 `resolve` 并在 note 里写明改了什么；不打算改的也 `resolve`，写清原因。
- 人说「等我批注」时，在后台跑 `mw comments <工程> --wait`，一有新批注就返回，处理完再挂上继续等。

## 6. 文字样式怎么编

样式结构见 `mw guide` 的 `textStyle`，常用的取舍：

- **高亮方式** `highlight.mode`：
  `keyword` 只亮标出的关键词（最克制，适合信息密集的讲解）；
  `current` 只亮正在念的字 / 词；`trail` 念过的都留亮；`sweep` 卡拉 OK 扫色。
  关键词在字幕条目的 `highlights` 里标，每句不超过 1–2 处，标多了等于没标。
- **出现节奏** `animation.unit` + `stagger` + `inSlot`：
  口播默认用剪映的节奏 `stagger: { fraction: 0.75 }` + `inSlot: 0.6`（内置 `caption-word-yellow` 就是这样）：
  前快后慢、比语音略早出完，看着利落。要严格跟着念的速度出字时用 `spread` 并跑 `align`。
- **装饰**（格式 v5）：
  - `highlight.activeBox`：正在念的词垫色块，节奏感最强，适合短句、快节奏；和 `current` 一起用时高亮色要和色块有对比。
  - `highlight.underline`：给关键词画线，比换色更安静；和荧光笔 `marker` 二选一。
  - `gradient`、`glow`：标题用得多，字幕慎用——小字号发光会糊，渐变要保证最浅的颜色在画面上也看得清。
  - 改完用 `preview --at` 截两三帧确认，装饰是否挡脸、是否出安全区也要看 `lint`。
- 人说「存成模板」「以后都用这个」时，用 `styles save` 存进库，写一句 description 说明适合什么内容。

## 7. 画面：转场、画中画、图片、关键帧

- **转场**（主轨片段的 `transitionIn`，加在第一段上不起作用）：口播大部分剪辑点直接硬切，转场只用在换话题、开场、接片尾这些地方，一条视频几处就够。
  `fade` 最安全；`slide` 是新画面滑进来盖住旧画面，`push` 是新画面把旧画面推走，`direction` 是画面往哪边走。
  时长一般 300–500ms。主轨转场**不占时间**：前一段停在最后一帧，和后一段的开头过渡，声音直接硬切，不会两句话叠在一起；
  接片尾的转场才会重叠、让总时长变短。加完用 `preview --sheet` 看衔接处。
- **画中画**：在一条非主轨的视频轨道上放 `FloatClip`（没有就先 `track.add` 一条 `kind: "video"`），
  用 `transform` 定位置和大小（x、y 是中心点，scale 按整幅画布缩放，素材按比例完整放进画布）。
  空镜、截图录屏一般不要声音：写 `gainDb: -60`。小窗不要挡脸和字幕，加完跑 `lint`。
- **图片**：`ImageItem`，用 `animIn` / `animOut` 加入场、出场动画（图片和画中画的 `slide` 从画面外滑进来，不写 `direction` 时从最近的边缘进出）；锚定用 `at: { caption, char }`，说到那个词时出现。
  需要一直有点动静时加 `animLoop: { preset: "breathe", durationMs: 2400, intensity: 2 }`（呼吸，v6；±3% 太弱看不出来），画中画也能用；同一画面里别多处同时呼吸。
- **关键帧**（`keyframe.set` / `keyframe.remove`，`atMs` 相对元素开始）：推近、缓慢移动、跟着内容走位。
  元素一旦有关键帧，`transform` 就不再起作用，以关键帧为准；推近 1.5–2.5 秒、幅度 10–20%：4 秒以上显得拖，1 秒以内像抖动。
  审片台上拖动、改数值会写进播放头处的关键帧。

## 8. 卡片和封面

- **卡片**是叠加层（`template` + `props`），先用 `mw guide` 的 `templates` 看有哪些：`useFor` 说明什么内容用它，`sizes` 是支持的尺寸，`example` 是能直接用的 props。
- 卡片必须写 `size`（v7）：`small` 一句金句、一个数字、人名、提示；`half` 要点列表、截图、超过 18 字的金句，出现时主画面自动上移；
  `full` 只在要展示整段原文这类情况用，会盖住标题条。有卡片时字幕自动隐藏。
- 少用：30 秒的视频 0–2 张，60 秒不超过 4 张（`lint` 会报 `TOO_MANY_CARDS`）。只给真正要记住的内容上卡。
- 字数守住模板的上限（`templates` 里 schema 的 `maxLength`），超了就精简，不要硬塞。
- 卡片锚在说到那件事的字幕上（`at: { caption, char }`），时长覆盖讲这件事的几句话，一般 2–6 秒；两张半屏卡挨着时，主画面不会中途落下来。
- 人说「第二个观点用半屏卡」这类话时，按章节定位：先确认 `chapters` 已经按观点分好（没有就先 `chapters.set`），
  第 N 个观点 = 开场之后的第 N 章；卡片锚在这一章里**亮出观点的那句字幕**（不一定是第一句），内容从这一章的字幕里提炼，
  不要编字幕里没说的话。分不清哪章算观点时，把你的理解列出来问人。
- **封面**：`cover.update` 写 `atMs`（挑表情、姿态好的那一帧，1 秒以后）和 `title: { template, style?, props }`，再跑 `cover`。
  封面只有主画面和封面标题，字幕、卡片、画中画都不会出现。

## 9. 不要做的事

- 不要直接改 `project.json`、`editor.json` 或素材文件。
- 不要为了通过 lint 去改人确认过的时长和文字。
- 不要在没确认的情况下批量加标题、卡片、强调动画。
- 不要删除人留的批注；处理完用 `resolve`。
