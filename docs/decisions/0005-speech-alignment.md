# 0005：本地识音对齐逐字时间（D27，工程格式 v2）

日期：2026-10-28

## 背景

阶段 A 复刻成片里，字幕逐词出现是把整句时长按字数平均分配。用户看完反馈：
「字幕动画有点快，没有跟着语音走」，并决定「要做，还是要识音」。

原计划把语音识别列为 v1 非目标。这里改的是**范围更小的一件事**：字幕文字仍然来自 SRT（剪映识别 + 人工校对），
识音只用来回答「每个字是什么时候念的」。

## 决定

1. **引擎**：[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0）的 Node 原生包 `sherpa-onnx-node`，
   模型用 SenseVoice small int8（`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`，约 230MB 解压后）。
   - 离线、本机运行，不需要 Python，不调用在线服务。
   - SenseVoice 是 CTC 模型，每个识别出的字都带开始时间；样片 16 句全部识完约 3 秒（M 系列 CPU）。
   - 模型不进仓库：`mw models --fetch` 下载到 `~/MediaWorkspace/models/`（`MW_MODELS_DIR` 可改）。
   - 没选 Whisper：中文字级时间戳要靠交叉注意力推算，不稳定；whisper.cpp 也要另外编译或装二进制。
   - 同一发布页上的 `…-int8-2025-09-09` 是**粤语微调版**（README 写明来自 WSYue-ASR），普通话口播不用它。
     在样片上两个模型都能用：逐字时间平均相差 22ms、最大 120ms（144 个字）。选官方普通话版。
2. **对齐**（`core/align.ts`，纯函数）：识别出的字和字幕原文做编辑距离对齐。
   - 对上的字（包括认错的同音字，例如「移民」认成「一边」）取识别的时间。
   - 漏识别的字按前后已知时间线性插值；多识别出的字（每句前后多截 300ms 音频带进来的邻句）跳过。
   - 标点不发音，和前一个字同时出现；结果单调不减，并限制在这句字幕的起止范围内。
3. **工程格式 v2**：`Caption.charStartMs?: number[]`，每个字（码点）开始念的**源时间**，和 `text` 一一对应（校验长度）。
   - 用源时间而不是时间线时间，和字幕本身一样（D19）：剪切、变速之后不用重新对齐，由 `compile` 映射到时间线。
   - 被剪掉的字：在显示段之前的算一开始就出现，之后的算到段末。
   - `caption.split` 跟着字拆开，并且默认在后半句第一个字开始念的时候断开；`caption.merge` 每句都有才拼接；
     `caption.update` 改了文字且字数变了，清掉旧的逐字时间（之后可以重新 `mw align`）。
   - 迁移 1 → 2 不改数据（新字段可选）。
4. **写入方式**：`mw align` 生成一批 `caption.update` 操作，经 `node/store` 提交，有 revision、历史和撤销；
   字幕轨道锁定时同样被拒绝（D18）。识别出的文字只出现在命令输出里（匹配率低于 0.8 的句子列在 `check` 中），不写回工程。
5. **渲染**：`unitStarts` 有逐字时间时，每个单位（词 / 字）从它第一个字开始念的时候出现，`stagger` 不起作用；
   没有时仍按字数分配整句时长。

## 后果

- 新增原生依赖 `sherpa-onnx-node`（macOS arm64 包约 34MB）。单元测试不依赖模型；`tests/asr.e2e.test.ts` 在没有模型时跳过。
- 以后阶段 C 的「念过的留亮」「卡拉 OK」高亮可以直接用 `charStartMs`。
- 以后如果要从零生成字幕（没有 SRT），可以在同一个引擎上做，但那是另一个决定。
