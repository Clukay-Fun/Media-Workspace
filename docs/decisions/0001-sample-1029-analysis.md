# 0001：1029 样片的剪辑方式

- 日期：2026-10-28
- 状态：已确认（数据分析结果）

## 背景

阶段 A 要求「只用 CLI，从 `剪辑前.mov` 做出和 `剪辑后.mp4` 效果接近的成片」，需要先知道样片是怎么剪的。
用户提供的 SRT 对应成片时间，没有对应原片的字幕。

## 分析方法

`scripts/align-edit.ts`：解码两段音频，计算 5ms 粒度的对数响度包络，拟合模型 `原片时间 = 倍速 × 成片时间 + 起点`。
（变速时保持音调，波形本身对不上，所以不用波形互相关。第一版用逐窗口波形互相关找剪辑点，结果是错的，已放弃。）

## 结论

| 项目 | 结果 |
|---|---|
| 剪辑方式 | 原片从 **2.607 秒**开始，**整体 1.1 倍速**，到原片约 32.38 秒结束，然后接片尾。**中间没有任何剪切** |
| 拟合质量 | 整体相关系数 0.925；逐秒相关系数都在 0.80 以上 |
| 成片构成 | 正片约 26.95 秒（809 帧）+ 片尾 1.76 秒（53 帧）= 862 帧 |
| 色彩 | 原片是 10-bit HEVC，但色彩是 bt709（SDR），**不是 HDR** |
| 片尾素材 | H.264、29fps、AAC 44.1kHz，需要标准化成 30fps、48kHz |

## 影响

1. **变速（F6）必须在阶段 A 实现**（数据和渲染），否则复刻不了样片。界面仍在阶段 D 做。
2. 阶段 A 验收的「剪辑点」改为「起点和倍速」：裁头 2.607 秒、1.1 倍速。
3. 主轨片段需要 `transform: { scale: 1.266, x: 542, y: 970 }`（中心点 = 画布中心 + 位移）。阶段 A 的数据和渲染已经包含 `transform`。
4. 参考线需要能**保存成预设**，新工程直接套用（例如「我的口播构图」）。
5. 推导出的对应原片的 SRT（当时放在 `fixtures/out/1029/source.srt`，不进仓库；可以用 `scripts/align-edit.ts` 重新生成）用作 `timebase: "source"` 的测试数据；
   原 SRT 用作 `timebase: "timeline"` 的测试数据。两种导入方式的结果应该一致。
6. 字幕样式的默认最大宽度取 859px（对应字幕对准线 x 106–965），超宽时换行或缩小字号，由 TextStyle 的排版规则处理。
7. 成片的滤镜（约暗 4%）不还原，阶段 A 验收不比较颜色和亮度。
