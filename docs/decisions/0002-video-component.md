# 0002：视频组件使用 @remotion/media 的 `<Video>`

- 日期：2026-10-28
- 状态：已采用
- 验证代码：`spikes/a0-2/`（`render.ts` 渲染，`verify.ts` 校验）

## 验证内容

用 `@remotion/media` 4.0.539 的 `<Video>` 渲染：标准化后的原片，`trimBefore = 78 帧`（2.6 秒）、`playbackRate = 1.1`、
`preservePitch`，时长 809 帧，再用 `<Series>` 接上 53 帧的片尾。输出 1080×1920、30fps、H.264 CRF 18。

## 结果

| 检查项 | 结果 |
|---|---|
| 画面帧准确性 | 抽查输出第 0、100、400、700、805 帧，对应的原片帧完全一致（PSNR 45–46dB，相邻帧只有 31–39dB） |
| 帧映射规则 | 输出第 n 帧 = 原片第 `trimBefore + floor(n × 倍速)` 帧（第 805 帧：78 + floor(885.5) = 963，不是四舍五入的 964）。**`core/compile` 必须用同样的规则** |
| 音画同步 | 输出音频和原片音频按模型对齐，偏差 **6ms**（小于 1 帧的 33ms），相关系数 0.975 |
| 和剪映成片对比 | 音频偏差 15ms，属于两个软件处理上的差异，在 1 帧以内 |
| 片尾衔接 | 第 808 帧到第 809 帧直接切换，没有黑帧；音频平滑衰减，没有爆音；片尾音频完整 |
| 渲染速度 | 862 帧用了 28.5 秒（M2、默认并发），**约等于实时**。首次运行需要下载 Chrome Headless Shell（约 171MB） |

## 注意事项

1. **`preservePitch` 默认是 `false`**。不打开的话，变速会改变音调（1.1 倍速声音变尖）。渲染组件里必须对所有视频和音频显式设置 `preservePitch`。
2. 媒体文件通过本地 HTTP 服务提供（`src/node/media-server.ts`），需要支持 Range 和 CORS。不用 `publicDir`，避免每次渲染都把素材复制进打包目录。
3. 片尾素材的峰值接近 0 dBFS，比口播响很多。阶段 A 先如实保留；是否做响度统一，在阶段 B 评估（PLAN.md 第 9 节）。
