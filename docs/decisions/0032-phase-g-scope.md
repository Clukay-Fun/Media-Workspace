# 阶段 G：可见的 MCP 制作与文字表现

> 状态：首批文字功能与双客户端 MCP 实测已完成（2026-11-03）；待本次合并提交进入 `dev`。字体授权未知项与客户端能力边界见下文。

## 实测结论（2026-11-03）

- Codex 和 DeepSeek 各以新工程通过 MCP 完成 1029 样例制作，自动操作的历史来源均为 `mcp`，中途人工修改保留在后续版本中；工程保持可播放、可继续编辑，未导出最终 MP4。测试细节与截图仅保存在本地 `local/notes/2026-11-03-g-codex-mcp-test/`、`local/notes/2026-11-03-g-dsh-mcp-test/`。
- DeepSeek 提交后服务端 SSE 发出工程变更事件；Sol 另用临时工程在 Chrome 验证，MCP 修改画幅后网页无需重载即更新画布与 AI 改动提示。DSH 自身没有浏览器控制工具，因此 DS 不能在客户端内目视网页，这属于客户端能力边界。
- `caption.reflow` 同一操作扩成更多行时曾因新 ID 重复而失败；已在 `src/core/ops.ts` 预留新 ID，并用扩行回归测试覆盖，DS 只读审查通过。合并工作区通过 `pnpm check`、366 个单测、16 个 e2e 和网页构建。
- 33 个字体家族的授权和 1029 字形覆盖分别记录在 `docs/font-licenses.md`；11 个家族的证据已闭环，其余 22 个家族仍有未知项。未知项不能推断为可商用或可随项目分发。

## 目标与工作方式

负责人提出制作要求后，支持浏览器的 AI 客户端打开本地审片台作为侧边画面，**通过 Media Workspace MCP 修改同一个工程**。网页实时展示工程变化、预览和时间线；鼠标只负责打开页面、检查画面和必要的人为验收，不代替 MCP 执行编辑。AI 做完编排、自查后停在“待负责人验收”的工程状态，保留可继续编辑的 `.mwproj`，**不自动导出 MP4**。负责人调整或批注后，AI 再处理；只有负责人明确要求导出时才调用 `export`。

现有基础：MCP 已有 `init`、`import`、`transcribe`、`apply`、`preview`、`lint`、`comments` 等工具；本地服务监听工程修改日志并通过 SSE 推送，网页收到版本变化会刷新；`export` 是独立工具。依据：`src/mcp/server.ts`、`src/server/events.ts`、`src/server/app.ts`、`src/web/store.ts`、`README.md`。浏览器侧边栏由 AI 客户端提供，仓库本身不控制外部客户端的面板布局；首轮先做操作协议与真实演示，不引入模拟点击。

## 范围

1. **可见制作流程**：先确定工程名与输入素材；AI 打开或指向本地审片台，MCP 逐步提交、在关键节点用 `preview`/`lint` 自查。页面应能看见新素材、字幕、标题、时间线与当前画面；AI 说明正在做哪一步及失败原因。处理版本冲突时重新 `inspect`，不覆盖人工修改。
2. **待验收交接**：流程末尾汇报工程路径、已做的剪辑与样式、检查结果、需要负责人决定的地方；页面停在可播放的工程，保留历史与批注入口。首轮不改工程格式；“待验收”先作为交接流程，不伪造为当前已有的工程状态字段。
3. **字体可用性与选择**：已有 `FONT_FAMILIES` 注册 33 个家族、87 个字重文件，`pnpm fonts:check` 本机通过；右栏选择器已按分组列出这些字体。先做清单：显示名称、字重、授权来源、缺字与回退、竖屏和横屏的预览/导出一致性。围绕桌面 `1029` 样例的口播字幕、大标题和封面挑常用字体，做易找的预览与筛选；没有证据支持公开使用的字体不列入推荐。字体文件继续留在本机，不提交仓库。依据：`src/core/fonts.ts`、`src/node/fonts.ts`、`src/web/components/inspector/text-style-editor.tsx`、`AGENTS.md` §1、负责人本轮指定的样例。
4. **大标题与字幕样式**：基于现有 `TextStyle` 扩展可复用组合预设，组合字体、字重、字号、填充/高亮色、描边、阴影、位置及一种入场效果；标题和字幕分别提供少量经过实片验证的预设与实时预览。保留“只改这一句”和“应用到共用样式”的范围选择。优先复用现有样式库与文本渲染，不为每个颜色组合新写模板。依据：`src/core/text-style.ts`、`src/core/presets.ts`、`src/web/components/inspector/text-style-editor.tsx`、`src/composition/TextBlock.tsx`。
5. **单一动画扩展**：底层 `AnimPresetName` 已定义多种效果，但右栏入场下拉目前只露出“无、fade、fade-up、pop、typewriter、color-sweep”。先逐个确认底层实际渲染、可读性与性能，再增加适合标题/字幕的单项入场、强调或出场预设；每次只选一个主效果，提供时长和逐字/逐词/整行等必要参数。预览与导出必须同帧一致。依据：`src/core/text-style.ts`、`src/core/animate.ts`、`src/composition/TextBlock.tsx`、`src/web/components/inspector/text-style-editor.tsx`。

## 本阶段不做

不自动导出、不发布成片；不开发自由组合动画时间轴或曲线编辑器；不引入在线字体服务；不让 AI 通过浏览器模拟编辑来绕过 MCP；不修改外部 AI 客户端的侧边栏实现。除非验收证明必须，否则不升工程格式。

## 1029 样片的首批文字方向（2026-11-03）

Grok 的逐帧记录和 Luna 的预设核对收敛到以下首批验收目标。它们是**这条样片的观察与实施方向**，不是所有账号的通用规范。图像证据只在 `local/notes/2026-11-03-1029-text-style/`，测量补充见 `local/notes/2026-10-30-phase-f/grok-measure/`。

- 正片两行标题从约 0.100 秒到 26.900 秒保持顶部静止，片尾时与字幕一起退出；开头约 0.000–0.067 秒是封面静帧，标题位置另设。首批正片标题不加弹出、上浮或滑动入场，封面不复用正片纵坐标。
- 口播字幕是白字重黑边、当前词更亮的黄色；词在最终位置很快淡实，不发生位移或缩放。首批保留短淡入与逐词高亮，其他动画只作为独立候选测试，不套在 1029 样片上。
- 标题金黄与字幕柠檬黄分别存放；逐帧取样的近似均值不是最终色值规范。当前内置 `title-bar-yellow`、`caption-word-yellow` 可作起点，另一个白字粗黑边样式仅是 MCP 测试工程的对照，不列为推荐。
- 断行先按词边界检查，避免“情况”“准备”“资金”拆开或留下单字尾行。原样片也出现这类断词，故不照抄其断点；不自动添加原文没有的标点。
- 验收抽查标题约 0.200、8.000、16.000 秒，字幕约 12.833 秒，以及上述断词段；对照网页预览与独立测试帧，分别看 9:16 和 16:9。样片实际字体无法由截图确认；工程配置的阿里巴巴普惠体 3.0 不能当成样片字体识别结论。

首批开发边界：DS 独占 `src/web/components/inspector/{caption,overlay,text-style-editor,common}.tsx`、`src/web/styles.css`、`src/composition/TextBlock.tsx` 和对应测试，完成字体/样式查找、预览、套用与 1029 效果核对；如需修改 `src/core/` 或其他公共文件，先交给 Sol 划定唯一修改人。Sol 负责 MCP 实操流程、最终抽帧和 Codex/DS 双客户端验收。具体目录与状态以 `docs/STATUS.md` 为准。

## 验收场景

- 只验收 **Codex 和 DeepSeek（DS）** 两个客户端；各用**新建测试工程**，以 `~/Desktop/1029/剪辑前.mov` 为原片，同目录 SRT、`剪辑后.mp4` 为文字与成片对照（SRT 的时间属于参考成片，不直接当原片时间导入）。AI 通过 MCP 完成制作，同时侧边审片台能看到连续更新。核对操作日志来源为 `mcp`，而不是网页模拟点击。中途人工修改一处，再让 AI 继续，确认没有覆盖人的修改。
- AI 宣告完成时，工程可播放，字幕和标题已套用文字预设，`lint` 与抽帧自查结果可复核；未产生新的最终 MP4。负责人能直接继续调整并留批注。
- 对选入常用区的字体，以 `~/Desktop/1029/剪辑后.mp4` 的标题、字幕表现及 `封面.jpg` 为观感基准；在 9:16、16:9 各抽取标题和字幕画面，比较网页预览与**独立测试输出帧**；有缺字时能看到预期回退。字体授权清单要能指向本地许可证或来源证据。样片和截图只读，不放进 `docs/`；带图分析放 `local/notes/`。
- 每个新增单项动画至少有静帧/关键帧检查与真实播放检查，确认进入、持续、退出时间可理解，渲染测试不回退。
- 代码改动遵守 `AGENTS.md`：`pnpm check`、`pnpm test`；涉及合成、字体媒体和动画渲染时加跑 `pnpm test:e2e`。
