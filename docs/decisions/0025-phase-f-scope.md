# 0025：阶段 F 盘点和分工

日期：2026-10-30。

## 背景

阶段 E 验收（0024）时四个 AI 都靠用户给的 SRT 出字幕，SRT 是按成片时间打的，不是原片；
和用户自己的剪辑（`剪辑后.mp4`）对比，还有几处差距：

| 问题 | 原因 |
|---|---|
| 人物位置每份都不一样，参考线没起作用 | 参考线只存在 `editor.json`（只给工作台看），AI 和渲染都不读；验收工程里也是空的 |
| 字幕把一个词拆在两行 | 每个字是单独的行内块，哪里都能断；全局 `text-wrap: balance` 让它更爱从中间断 |
| AI 按通用「全平台」安全区躲，反而离开了用户的版式 | lint 只知道通用安全区，不知道用户自己的版式 |
| 用了不需要的半屏卡 | 验收的那句话里要求了半屏卡；这段 28 秒的片子用不上 |
| 剪停顿靠字幕空隙 | 字幕时间不准时剪不到；0024 用响度收回了结束时间，但还是从字幕出发 |

阶段 F 的目标：**只给原片和一段纯文本文稿**（不给 SRT），AI 出的片子和用户自己剪的接近。

## 决定

### 账号级版式

版式（参考线、人物位置、标题条和字幕的位置）是账号级的，所有工程共用，和默认片尾一样放在
`~/MediaWorkspace/library/layout.json`。用户的参考图上参考线是：竖中线 50%；横线 25.2%（头顶）、51.3%（下巴 / 领口）、60.8%（领夹麦）。
内容大致是：

- `guides`：参考线列表（横 / 竖、位置占画面的比例、名字），工作台显示、导出参考线叠加图时用；
- `face`：人脸框落在哪里（中心 x、上沿 y、下沿 y，占画面比例），`mw frame` 用它算主画面的缩放和位置；
- `titleBar`、`caption`：标题条、字幕的样式和位置。

工程的 `editor.json` 参考线保持只给工作台用；新工程默认显示账号版式的参考线。
lint 改为检查和账号版式的偏差（人脸偏离、字幕 / 标题条位置不同）；通用安全区降为提示。

### 字幕从原片识音生成，文稿校字

- `mw transcribe <proj>`：SenseVoice 识别原片，按停顿和标点断句，一句一行（参考成片每行不超过约 14 个字）。
- 粘贴的纯文本文稿用来校字：字以文稿为准，时间用识音的；对不上的地方（漏读、多读、改口）列出来给用户确认，不自己猜。
- 字幕换行按词：不在词中间断，能一行就一行；字幕去掉 `text-wrap: balance`，卡片保留。

### 编排规则

- 卡片按内容需要才用，短视频默认不用，AI 可以建议不用。
- 人物位置一律用 `mw frame` 按账号版式算，不手调。
- 停顿按音频静音剪，不按字幕空隙。

## 分工

- **Claude**（dev）：账号版式（core 格式 + `node/library` 读写 + API），`mw transcribe`，文稿校字，字幕按词换行，
  `mw frame` 的计算，编排规则和 `mw guide`，工作台里编辑、保存账号版式和参考线，最后的验收。
- **Codex**（`media-workspace-codex` / `feat/silence-compare`）：按音频静音剪停顿；`mw compare <proj> <参考成片>`
  出对比图，列出时长、剪切点、人物位置、字幕换行的差别。
- **Grok**（`local/notes/`，不写代码）：量用户的成片 `剪辑后.mp4`——字幕每行字数、断行位置、人物位置（人脸框）、标题条和字幕的位置，
  作为默认版式和断句规则的依据。

DeepSeek 从阶段 F 起不再参与，原来给它的工作台部分由 Claude 做。

## 验收

新开 AI 会话，只给原片 `剪辑前.mov` 和纯文本文稿，一句话让 AI 出片；用 `mw compare` 和 `剪辑后.mp4` 对比。
阶段 E 先不合 main，阶段 F 验收后一起由 dev 开 PR。
