# 0017：阶段 D 盘点和分工

日期：2026-10-30。

## 背景

阶段 D 的范围是变速（F6）、转场（F7）、图片 + 动效（F8）、画中画（F15）、关键帧界面（F16），
验收标准是「每项功能在界面和 CLI 中都能使用，预览和导出一致」。
开工前逐项核对了数据、渲染、CLI / MCP、界面、测试五层：

| 功能 | 数据 / 操作 | 渲染 | CLI / MCP | 界面 | 测试 |
|---|---|---|---|---|---|
| F6 变速 | `speed` 0.1–10 | `playbackRate` + 保留音调 | 有 | 属性面板（0015） | 单测；导出测试里用了 1.5 倍 |
| F7 转场 | `transitionIn`：slide / push / fade | `TransitionSeries`，但 push 和 slide 画面一样 | 只能 `item.update` | 没有 | 只有 compile 单测 |
| F8 图片 + 动效 | 入场 / 出场 + 关键帧；没有循环动画 | 有 | 有 | 属性面板有；素材区放不到画面上 | 没有导出测试 |
| F15 画中画 | 第二条视频轨道 + `transform` | 有 | 有 | 能拖位置；没有选中框和缩放手柄 | 没有导出测试 |
| F16 关键帧 | `keyframe.set` / `keyframe.remove` | `transformAt` 插值 | 有 | 没有 | 插值、分割的单测 |

另外发现两个问题：

1. 有关键帧的元素，`transformAt` 只看关键帧，`transform` 不起作用。审片台上拖动、属性面板改数值都写进 `transform`，
   画面不变，也没有提示。
2. 点选框（`web/lib/geometry.ts`）按 `transform` 算，没按当前帧的关键帧位置算，有关键帧的元素点不准。

`mw guide` 和 `docs/orchestration-guide.md` 里没有转场、画中画、关键帧的规则，AI 不知道这些能力。

## 决定

变速已经完成，不再动。其余按下面分工，前三项同时开工：

- **Claude**（dev）：修上面两个问题——有关键帧的元素，拖动和改数值写进播放头处的关键帧
  （播放头正好在某个关键帧上就改它，否则新加一个）；点选框按当前帧的变换算。
  push 改成真正的推（旧画面被推走），slide 是新画面滑进来盖住旧画面；工程格式不变。
  导出测试补上转场、图片、画中画、关键帧，比对截图和导出帧；`mw guide` 和编排说明补上规则。
- **Codex**（`feat/keyframe-ui`）：关键帧界面——属性面板列出选中元素的关键帧（在播放头处加一个、删除、跳过去、改缓动），
  时间线片段上标出关键帧位置。
- **DeepSeek**（`feat/pip`）：画中画——非主轨视频显示选中框、拖角缩放、四角小窗预设；
  素材区「放到画面上」，图片和视频都能用，没有合适的轨道时自动新建。
- **Grok**（`local/notes/`，不写代码）：调研口播视频常用的转场和图片循环动画，给出推荐的几种和参数。

转场界面（时间线上两段之间加转场、显示转场）和循环动画等调研出来后作为第二批，循环动画要加字段，
到时候按格式变更的规则升版本。
