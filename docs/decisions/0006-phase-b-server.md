# 0006：阶段 B 的本地服务、MCP 和编辑纯函数

日期：2026-10-28

阶段 B 分两路并行：界面（`src/web`）由另一个 agent 开发；本记录是服务端、MCP、core 纯函数这一路的设计决定。
两边只通过 `src/core/api.ts`（接口约定）和 `src/core/edit.ts`（编辑纯函数）对接。

## 决定

1. **接口约定放在 core**（`core/api.ts`）：路由、请求 / 返回类型、SSE 事件、编辑器状态 schema、错误码 → HTTP 状态。
   预览参数 `PreviewProps` 也移到这里，合成组件的 `MainProps` 直接复用，保证网页预览和导出用同一份结构。
2. **推送只有一个来源**：服务端监听工程的 `logs/` 目录。store 提交时最后一步才追加日志，
   日志里出现新版本时 `project.json` 一定已经写好；界面、CLI、MCP 的修改都走这一条路，不会漏也不会重复。
   实测从 CLI 提交到 SSE 送达在 1 秒以内（`src/server/app.test.ts` 有断言）。
3. **媒体**：预览用 540p 代理文件，通过已有的媒体服务（另一个端口，支持 Range，只提供登记过的文件）提供；
   `/api/preview` 返回的 props 里已经是可以直接播放的 URL。
4. **只接受本机访问**：服务只监听 127.0.0.1（D9），并检查 Host 头，防止网页通过 DNS 重绑定访问本地服务。
5. **撤销 / 重做**（`core/undo.ts`）：从修改日志推算撤销栈；撤销 = 回退到上一版（作为新的一版写入），
   所以撤销本身也有历史，人和 AI 的修改在同一个栈里，可以一键撤销 AI 的修改。
   撤销同样遵守 revision 检查和轨道锁定；和 ops 一致，锁定的轨道仍然可以改锁定 / 隐藏 / 静音开关（这样「锁定」本身也能撤销）。
6. **编辑纯函数**（`core/edit.ts`）：时间线拖动（移动 / 裁剪开头 / 裁剪结尾）、分割、预览画面的移动缩放。
   - 输出「松开时提交的 ops」和拖动中的本地预览，一次手势只提交一次（D23）。
   - 主轨磁吸：移动 = 换顺序，裁剪 = 改入点出点，开头位置不变。
   - 普通轨道拖动后改成绝对时间，不再跟随原来的锚点（和剪映一致）。
   - 字幕按源时间平移（D19），不能拖到对应素材以外；有逐字时间时一起平移，分割时在播放头之后第一个开始念的字处断开。
7. **CLI、MCP、服务共用 `node/actions.ts`**：截图、导出、封面、导入、识音、guide 原来写在 CLI 里，
   移到 node 以后三个外壳只做参数解析和输出（AGENTS.md 第 2 节）。新增错误码 `USAGE`（参数错误，CLI 退出码 2，HTTP 400）。
8. **MCP 工具和 mw 命令一一对应**：guide、inspect、validate、apply、import、align、preview、export、cover、
   history、undo、redo、revert。`preview` 直接返回 PNG 图片，AI 可以看图自查。出错时 `isError = true`，
   内容和 CLI 的错误 JSON 一致。
