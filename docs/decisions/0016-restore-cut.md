# 0016：恢复剪辑点（「恢复这一刀」）

日期：2026-10-30。

## 背景

AI 粗剪时用 `cut.removeCaptions` 删句，主轨片段上会留下 `cutBefore`（剪掉了什么），审片台在时间线上标出来。
用户能看到「这里剪掉了一截」，但只能整体撤销到那一步，没法只把某一刀恢复回来——
后面做过的修改都会跟着撤掉。

## 决定

1. **新增操作 `cut.restore {clip}`**（工程格式不变，不升版本）：`clip` 是剪辑点后面的主轨片段。
   要求前一个片段是同一个素材、且两段之间有空隙（`prev.outMs < clip.inMs`），否则报 `INVALID_OP`。
   做法是**把前一段延长到 `clip.inMs`**，去掉 `clip.cutBefore`；不把两段合并，
   这样后一段自己的变换、音量、关键帧都原样保留。只按普通分割切开的（没有空隙）不算剪辑点。
2. **字幕从历史里找回**（`node/actions.ts` 的 `restoreCut`）：`cut.removeCaptions` 会把字幕一起删掉，
   光接回画面字幕会缺一句。核心层没有历史，所以由 node 层从新到旧翻 `history/`，
   找同一素材、时间落在被剪区间里、现在已经不在工程里的字幕，取最新的版本（逐字时间、高亮都在），
   用 `item.add` 按时间顺序插回原来的轨道。和现有字幕时间重叠的（比如后来又新写了一句）不放回，
   在返回值 `skipped` 里列出来。
3. **一次提交**：`cut.restore` 和找回字幕的 `item.add` 放在同一批 ops 里，撤销一次就全部回去。
4. **三个入口同一个函数**：HTTP `POST /api/restore-cut`、CLI `mw uncut <工程> <片段>`（`--dry-run`、`--base`）、
   MCP 工具 `uncut`。界面在选中带剪辑标记的主轨片段时，右栏显示「恢复这一刀」。
   演示数据（mock）没有历史，只接回画面。

## 验证

- 单元测试：`core/ops.test.ts`（接回、非剪辑点报错）、`node/actions.test.ts`（找回字幕带逐字时间和高亮、重叠时跳过、dry-run）。
- 在阶段 C 验收工程的副本上恢复「那这条路径呢」：主轨接回 1.1 秒，字幕 s6 回来且逐字时间完整，
  其他两处剪辑不受影响，撤销一次回到剪辑后的状态；审片台点按钮后提示「已恢复剪掉的 1.1 秒，找回 1 句字幕」。
