## 0. 一句话定义

一个运行在本机的口播剪辑工作台：**AI 和人编辑的是同一份数据**。
AI 应用（Codex、Claude Code 等）通过 CLI 或本地 MCP 提交操作；
人在本地网页的**审片台**上实时预览、点选元素、写批注交给 AI 处理，只做少量直接微调（D28）。
所有界面修改最终也转换成同一套操作（ops），最后由 Remotion 渲染成 MP4。

## 2. 样片分析（`~/Desktop/1029`）

| 文件 | 参数 | 结论 |
|---|---|---|
| `剪辑前.mov` | HEVC Main10（10-bit）、1080×1920、**bt709（SDR）**、约 30fps、33.9 秒、AAC 48k 立体声 | 不是 HDR；10-bit HEVC 仍然要转成 8-bit H.264 标准化文件 |
| `剪辑后.mp4` | H.264、1080×1920、恒定 30fps、28.7 秒 | 原片从 2.607 秒开始、**整体 1.1 倍速**，中间没有剪切，最后接片尾（见 `docs/decisions/0001`） |
| `*.srt` | 16 条，0.3–27.1 秒 | **对应成片时间**，不对应原片 |
| `封面.jpg` | 1080×1920 | 人物画面 + 中间一条半透明深色横条 + 两行黄色大字标题 |

成片的画面结构（这也是阶段 A 要复刻的效果）：

1. **顶部固定标题条**：深色半透明横条，两行黄色粗体大字，黑色描边，整条视频一直显示。
2. **画面中部字幕**：白字黑描边，位置大约在画面高度的 60%（人物胸前），**逐字出现**，句末的关键词用黄色或黄绿色高亮。
3. **画面位置**：人物画面固定放大约 126.6%，向右约 2px、向下约 10px，全片不变，没有关键帧推近（见 `docs/decisions/0001`）。
4. **片尾关注卡**：黑底，圆形头像，加号动画变成对勾，「记得点赞关注哦 / -方便下次找到我-」，大约 1.5 秒。用户有现成的片尾素材，直接拼接，不用代码模板重做。

> 样片是 SDR，说明你的 iPhone 很可能已经关闭了 HDR 视频。HDR 处理从「阶段 A 必做」降为「检测到 HDR 就处理」（见第 8 节）。

## 4. 已确定的决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 不复用 OpenChatCut 的源码和工程格式 | 项目体量过大；它是 AGPL 协议 |
| D2 | 渲染引擎用 Remotion 4 | 动效写成 React 组件，预览和导出共用；转场有官方的 `@remotion/transitions` |
| D3 | 全栈 TypeScript，不用 Rust | Remotion、MCP SDK 都以 TS 为主 |
| D4 | `project.json` 是渲染的唯一数据源 | AI 和人修改的是同一份数据 |
| D5 | 所有修改都通过**操作（ops）**完成，界面操作也不例外 | 可以校验、记日志、撤销；AI 和人的修改可以互相看见 |
| D7 | 纯函数 `compile(project) → ResolvedTimeline` 是唯一的时间换算入口 | 预览、导出、校验、时间线、吸附都读它的结果 |
| D8 | 素材导入时统一生成标准化文件和预览代理；原始素材只读 | 解决 10-bit HEVC、可变帧率、旋转、拖动卡顿 |
| D9 | 只在本机运行，服务只监听 `127.0.0.1` | 不需要鉴权和隧道 |
| D10 | 单个 package，用 lint 规则约束模块边界 | 保持简单 |
| D11 | 仓库公开，代码用 MIT 协议 | Remotion 有自己的授权条款，不随 MIT 授予 |
| D13 | 默认字体用阿里巴巴普惠体 3.0，不进仓库；测试用 Noto Sans SC | 用户决定；避免授权问题 |
| D14 | 默认安全区取抖音、视频号、小红书的并集 | 一份成片三个平台都能发 |
| D15 | 命令名 `mw`，工程后缀 `.mwproj`，默认放在 `~/MediaWorkspace/projects/` | 工程约定 |
| ~~D16~~ | ~~产品定位：AI 编排 + 剪映式手动编辑，两种方式能力相同~~（被 D28 取代） | |
| **D17** | 采用**显式轨道模型**：一条磁吸主轨 + 多条普通轨道（第 5.2 节） | 轨道锁定、隐藏、静音和画中画都需要轨道 |
| **D18** | **轨道锁定对 AI 同样有效**：锁定轨道上的修改一律被拒绝（`TRACK_LOCKED`） | 人可以把满意的部分锁住，不让 AI 改动 |
| **D19** | 字幕绑定**素材源时间**（`asset + 源毫秒`），不绑定片段 | 分割、裁剪、删除、字幕快剪之后都不用重新绑定 |
| **D20** | 字幕、标题、卡片文字共用**一个文本样式引擎**，样式是 JSON | 用户可以自己编排样式，存成模板；AI 也能直接修改 |
| **D21** | 动画分两类：**声明式预设**（JSON 参数，用户可以编排）和**代码模板**（MG 卡片，用 React 编写） | 简单动画人人能调；复杂动态图形交给代码 |
| **D22** | 编辑器状态（参考线、标尺开关、缩放、选中）存在 `editor.json`，不影响渲染，也不增加 revision | 拖动参考线不应该和 AI 的修改发生冲突 |
| **D23** | 拖动过程中只更新本地预览，松开时提交**一次**操作 | 避免每次拖动产生上百个版本 |
| **D24** | 坐标改为**自由坐标 + 命名槽位**：人用标尺和参考线自由摆放，AI 优先用槽位（槽位会换算成坐标） | 参考线和标尺意味着需要自由定位 |
| **D25** | 工程格式**严格校验**：出现不认识的字段就报错（`UNKNOWN_FIELD`），不悄悄丢掉 | AI 拼错字段名时能立刻发现，而不是效果没生效还不知道为什么 |
| **D26** | 字体写成**字体栈**：主字体 + 后备字体，每个都对应具体的字体文件；不退回系统字体 | 生僻字、英文符号缺字时有确定的后备，预览和导出一致 |
| **D27** | **本地识音对齐**：用 sherpa-onnx + SenseVoice 离线识别，把识别出的字和字幕原文逐字对齐，得到每个字开始念的时间（`charStartMs`）；识别出的文字不写回工程 | 用户要求逐字动画跟着语音走；字幕文字已知，只缺时间。离线、模型约 230MB，不依赖 Python（`docs/decisions/0005`） |

| **D28** | **AI 主导编排，界面是审片台**：实时预览、点选、批注（`review.json`，AI 通过 MCP 读取和标记处理）、少量直接微调、撤销 / 锁定；时间线只做移动、裁剪、分割（修订见 `docs/decisions/0009`） | 实际用法是 AI 生成、人看片提意见；用文字描述「哪里、哪个元素」很费劲，点一下更准；手动剪辑投入大、用得少（`docs/decisions/0008`） |

（D16 被 D28 取代；D6 被 D19 取代；D12 被样片分析结果修正，见第 8 节。）

## 5. 工程格式 v1

### 5.1 工程目录

```
<name>.mwproj/
  project.json          # 渲染的唯一数据源
  editor.json           # 编辑器状态：参考线、标尺、时间线缩放、吸附开关（不影响渲染）
  review.json           # 审片批注（不影响渲染，不增加 revision；D28）
  history/              # 每次写入前保存的上一版（默认保留 200 版，用于撤销）
  logs/ops.jsonl        # 每次 apply 的记录：时间、来源(cli|mcp|ui)、操作者、ops、revision
  logs/render/          # 渲染日志
  captions/             # 导入的 SRT 原文件副本
  cache/media/          # <hash>.mez.mp4、<hash>.proxy.mp4、<hash>.probe.json、<hash>.peaks.json（波形）
  cache/stills/         # 截图
  renders/              # 成片和封面
  .lock
```

全局模板库：`~/MediaWorkspace/library/`（`text-styles/`、`titles/`、`presets/`、`outros/`）。
`outros/` 里可以放默认片尾素材，新建工程时自动使用。
工程里用到的模板会**复制一份**到 `project.json` 里，这样模板库以后改了，旧工程打开后效果也不变。

### 5.3 时间模型

- 存储单位统一用**整数毫秒**；只在 `compile()` 里换算成帧。
- **主轨**：片段首尾相连。片段在时间线上的长度 = `(outMs - inMs) / speed`；有转场时，和前一个片段重叠 `durationMs`（和剪映一样，转场会让总时长变短）。
- **普通轨道**：每个条目用 `at` 锚定开始位置：
  1. `{ "caption": "s5", "offsetMs"?: 0 }`：跟随某句字幕（推荐，AI 默认用这种）。
     加 `"char": 3` 表示念到这句第 4 个字时出现（v3，`docs/decisions/0007`）。
  2. `{ "clip": "c2", "offsetMs": 300 }`：跟随主轨上的某个片段。
  3. `{ "ms": 9000 }`：成片的绝对时间（人在时间线上拖动后默认是这种）。
- **字幕**：记录的是 `asset + 源时间`。主轨上任何一个片段只要露出了这段源时间，就在对应位置显示；变速时按倍速换算；被剪掉的部分就不显示。
  因此，分割、裁剪、删除片段、字幕快剪之后，字幕都**不需要重新绑定**。
- 导入 SRT 时有两种时间基准：
  - `timebase: "source"`：SRT 对应某个**原片**（字幕快剪需要这种），直接绑定。
  - `timebase: "timeline"`：SRT 对应**当前的成片时间线**（你样片里的 SRT 就是这种），按主轨的映射关系反算回源时间。

### 5.4 文本样式引擎（TextStyle）

字幕、标题、卡片里的文字都用同一个样式结构，用户可以自己编排，并另存为模板：

```jsonc
{
  "font": { "family": "alibaba-puhuiti-3", "fallback": ["noto-sans-sc"],
            "weight": 700, "size": 64, "letterSpacing": 0, "lineHeight": 1.25 },
  "fill": "#FFFFFF",
  "stroke": { "color": "#000000", "width": 6 },
  "shadow": { "color": "#00000099", "blur": 8, "x": 0, "y": 4 },
  "box": null,                    // 背景框：{ "color": "#000000AA", "radius": 12, "padding": [8, 16] }
  "layout": { "x": 540, "y": 1160, "anchor": "center", "maxWidth": 920, "maxLines": 2, "align": "center" },
  "highlight": { "fill": "#FFD400", "stroke": null, "scale": 1.0, "anim": "pop" },
  // 阶段 C 加入：高亮方式 mode（keyword = 只亮关键词；current = 只亮正在念的字 / 词；trail = 念过的都留亮）、
  // 当前词底下的圆角色块 activeBox、下划线 underline、高亮的字的 gradient / glow（docs/decisions/0012，格式 v5）
  "gradient": null,               // 竖直渐变：{ "colors": ["#FFFFFF", "#9FD8FF"] }，代替 fill
  "glow": null,                   // 发光：{ "color": "#3AA0FF", "blur": 16 }
  "timing": { "leadMs": 0, "tailMs": 0, "handoff": "cut" },  // 提前出现、延后消失；相邻两句 cut = 直接切换，overlap = 允许重叠
  "animation": {
    "in":  { "preset": "fade-up", "durationMs": 180, "easing": "ease-out" },
    "unit": "char",               // char | word | line：逐字、逐词、整行
    "stagger": "spread",          // spread = 在字幕时长内均分（不代表真实发音时间）；或者填固定毫秒数
    "out": { "preset": "fade", "durationMs": 100 },
    "loop": null
  }
}
```

**动画预设库**（声明式，所有参数都可以调），分四类：

| 类别 | 预设 |
|---|---|
| 入场 | `fade`、`fade-up`、`slide`（上 / 下 / 左 / 右）、`pop`（缩放弹出）、`scale-punch`（回弹放大）、`bounce`、`slam`（砸落）、`wave`（逐字波浪）、`typewriter`、`blur-in`、`zoom-in`、`color-sweep`（颜色扫过，按时长均分） |
| 强调 | `pulse`（放大一下再回来）、`glow`（发光）、`color-shift`（变色）、`shake`、`underline-sweep`（下划线划过）。在某个时间点上播放一次，用于关键词 |
| 出场 | `fade`、`slide`、`zoom-out`、`scale-out` |
| 循环 | `breathe`（循环缩放） |

同一套预设同时用于文字、图片和画中画。每个预设带一个**情绪标注**（沉稳 / 冲击 / 俏皮 / 科技 / 柔和），
`mw guide` 输出给 AI，方便 AI 按内容挑选动画。

样式属性在界面上按**位置、外观、时间**三组展示，分组信息写在 schema 的元数据里，样式面板按它自动生成，不另外维护一份属性列表。

### 5.5 坐标和槽位

- 画布坐标以像素为单位，原点在左上角。`transform`：`x`、`y`（中心点）、`scale`、`rotation`、`opacity`、`radius`（圆角）、`crop`（画中画可以裁切，主轨不裁切）。
- 槽位：`top`、`upper-third`、`center`、`lower-third`、`caption`。AI 可以只写槽位，`compile` 会结合安全区换算成坐标；人在界面上拖动后会写入具体坐标。
- 安全区预设（1080×1920，像素边距，初始估计值，阶段 B 用平台截图校准）：

| 预设 | 上 | 下 | 左 | 右 |
|---|---|---|---|---|
| `douyin` | 160 | 420 | 60 | 160 |
| `channels`（视频号） | 170 | 400 | 60 | 150 |
| `xiaohongshu` | 180 | 360 | 60 | 150 |
| **`all`（默认）** | 180 | 440 | 60 | 170 |

## 6. 操作协议（ops）

### 6.1 操作列表

| 分类 | 操作 |
|---|---|
| 工程 | `canvas.update`、`theme.update`、`cover.update`、`outro.set`、`outro.remove` |
| 素材 | `asset.add`、`asset.relink`、`asset.remove` |
| 轨道 | `track.add`、`track.update`（锁定、隐藏、静音、改名）、`track.move`、`track.remove` |
| 片段 | `item.add`、`item.update`、`item.move`（可以换轨道）、`item.remove`、`clip.split`、`clip.trim` |
| 关键帧 | `keyframe.set`、`keyframe.remove` |
| 字幕 | `caption.import`、`caption.update`、`caption.remove`、`caption.merge`、`caption.split` |
| 字幕快剪 | `cut.removeCaptions`（删除这些字幕对应的画面）、`cut.removePauses`（去掉超过阈值的停顿，保留余量） |
| 样式 | `style.add`、`style.update`、`style.remove`、`style.saveToLibrary` |

### 6.2 规则

- 一次 `apply` 提交一批操作，**要么全部成功，要么全部不生效**。
- 每次都要带上 `baseRevision`；版本不一致时返回 `CONFLICT`。
- 修改锁定轨道上的条目时返回 `TRACK_LOCKED`，**无论操作来自人还是 AI**。
- 新建对象时可以不传 `id`，由系统生成并返回。
- 返回结果：`{ ok, revision, changed: [ids], warnings: [...] }`。
- **撤销 / 重做**：界面上的撤销会回退到自己上一次操作之前的版本。如果中间有 AI 的修改，先提示，再决定是否一起撤销。

### 6.3 校验

- **validate（错误，阻止写入）**：schema 不合法、引用不存在、时间越界、锁定轨道、模板参数不合法、素材缺失、字体缺失。
- **lint（警告，不阻止写入）**：同一槽位的元素时间重叠、字幕被截断、文字超出容器（`measureText`）、效果过密、元素超出安全区、转场比相邻片段还长、锚点字幕已被剪掉。
- 错误格式：`{ code, path, message, hint }`。

## 8. 媒体处理

1. **probe**：时长、分辨率、帧率（是否恒定）、编码、位深、色彩传递特性、旋转、音频参数。
2. **标准化文件（mez）**：素材**不是**「H.264 8-bit + 恒定 30fps + SDR bt709 + 无旋转 + AAC 48k」时，转出 `*.mez.mp4`（libx264 CRF 18）。
   样片 `剪辑前.mov` 是 10-bit HEVC，**需要转换**。
3. **预览代理**：540×960、CRF 23、GOP 15 帧，用于在界面里拖动定位。
4. **波形**：用 ffmpeg 生成音量峰值数据 `*.peaks.json`，在时间线上显示，帮助找停顿位置。
5. 分辨率不是 9:16 的素材：按比例缩放并加黑边，不裁切，给出 lint 警告。
6. **HDR**：检测到 HLG 或 PQ 时才处理。本机默认的 ffmpeg 8.1 不支持正确的色调映射，到时需要安装 `ffmpeg-full`（Homebrew，keg-only）或使用 macOS 自带的 `avconvert`。
   遇到 HDR 素材之前不做这部分；遇到时，在支持之前**直接报错**，不静默输出颜色错误的视频。
7. 图片：支持 PNG、JPG、WebP；HEIC 导入时转成 JPG 缓存。

## 9. 渲染

- 预览（Player）和导出（`renderMedia`）用同一个 `composition/Main`，输入都是 `ResolvedTimeline`。
- 视频组件用 `@remotion/media` 的 `<Video>`（已验证，见 `docs/decisions/0002`）；变速用 `playbackRate`，**必须显式打开 `preservePitch`**（默认关闭）。
- 帧映射规则：输出第 n 帧 = 源素材第 `trimBefore + floor(n × 倍速)` 帧，`core/compile` 必须和它一致。
- 媒体通过本地 HTTP 服务（支持 Range 和 CORS）提供给渲染器和预览，不使用 `publicDir`。
- 转场用 `@remotion/transitions`（`slide`、`wipe`、`fade`），方向和时长可以配置。
- 字体用 `@remotion/fonts` 显式加载；缺失时报错 `FONT_MISSING`。阶段 B 评估在预览里使用子集字体。
- 输出参数：H.264、yuv420p、bt709、AAC 48k 192kbps、CRF 18；并发数默认取 CPU 核数的一半；阶段 A 评估 VideoToolbox 硬件编码。
- 隐藏的轨道不渲染，静音的轨道不输出声音。
- 渲染失败不修改 `project.json`；每次渲染都写日志。

## 11. 里程碑与验收

### 阶段 A：内核 + CLI（复刻样片）

范围：core（schema、ops、validate、compile、srt、snap 的纯逻辑）、node（store、media、render），
文本样式引擎和动画预设（字幕、高亮、逐字出现），标题模板 `title-bar`，片段 `transform` + 缩放关键帧，
`clip.split`、`caption.import`（两种时间基准）、`cut.removeCaptions`、`cut.removePauses` 的操作层，以及完整的 CLI。
工程格式严格校验（D25）、字体栈（D26）、字幕显示时间字段 `timing`（提前 / 延后 / 衔接）。

验收：**只用 CLI，从 `剪辑前.mov` 做出和 `剪辑后.mp4` 效果接近的成片**：

1. 顶部固定标题条：样式接近，整条视频一直显示。
2. 中部字幕：逐字出现，关键词高亮，时间和画面对应；字幕中心在 y≈1167，横向不超出字幕对准线（x 106–965）。
3. 起点和倍速和成片一致：裁掉开头 2.607 秒，1.1 倍速，声音保持原来的音调。
4. 画面缩放和位置与成片一致（126.6%，位移约 +2px、+10px），用 `preview` 叠加参考线检查。（成片加了滤镜，不还原，不比较颜色和亮度）
5. 音频在切点处没有爆音。
6. 截图（`preview`）和导出视频的对应帧一致；黄金帧测试通过。
7. 冲突、校验失败、渲染失败、锁定轨道四种情况下，`project.json` 都不会被损坏；可以回退。
8. 成片最后接上你自己的片尾素材，衔接处没有黑帧、爆音。

> A0-2 验证了视频组件的帧准确性和音画同步（`docs/decisions/0002`，验证代码在提交 df1e29b 的 `spikes/a0-2/`，之后已删除）。

### 阶段 B：审片台

范围：Hono 服务（REST、SSE、媒体 Range 请求）、MCP stdio 服务（和 CLI 一一对应），以及第 10 节的审片台界面：
实时预览、点选、拖动位置、出现时间微调、改字幕文字、样式库套用、批注（`review.json`）、质检和 AI 改动标记、
轨道锁定 / 隐藏 / 静音、撤销 / 重做、导出进度。

验收：

1. 看片时在某个时刻点选一个元素，写一条批注；AI 通过 MCP `comments` 读到它（带时间点和条目 ID），
   修改后 `resolve`，界面在 1 秒内刷新工程和批注状态，并高亮改动。
2. 用 CLI 或 MCP 修改工程后，打开着的界面在 1 秒内刷新并高亮改动；在界面里可以一键撤销 AI 的修改。
3. 轨道锁定后，AI 修改这条轨道会收到 `TRACK_LOCKED`。
4. 拖动叠加层位置、调整出现时间、改字幕错字、套用样式都只提交一次操作；基于旧版本的提交返回 `CONFLICT`，界面提示并刷新。
5. 在界面上导出，能看到进度，导出结果和预览一致。

### 阶段 C：字幕体系

范围（界面部分按 D28 再评估，优先做成 AI 能用的能力）：字幕快剪视图（F11）、文本样式编辑面板（F5）、字幕模板库（F13）、标题模板库（F14）、模板库的保存和导入；
字幕高亮方式（只亮关键词 / 只亮当前字 / 念过的留亮）、当前词色块、下划线、渐变、发光；强调类动画。
`docs/orchestration-guide.md` 的第一版写进 AI 自查流程：先列方案再提交操作；提交后 `validate` + `preview --sheet` 自查，
只修一轮；修的时候不能改动已经确定的时长。

验收：在文稿视图里删除 3 句、合并 2 句、去停顿之后，导出的成片剪辑点正确；自己编排一个字幕样式，保存成模板，在另一个工程里使用。

> **v0.8 修订（`docs/decisions/0011`）**：大部分高亮和快剪操作已在阶段 A / v0.7 完成。阶段 C 收窄为：
> 样式模板库（`mw styles`、MCP `styles`、左栏模板库，已完成）→ 逐字动画更顺滑 → 当前词色块 / 下划线 / 渐变 / 发光（格式 v5，已完成，`0012`）
> → `docs/orchestration-guide.md`（第一版已完成，阶段 E 补 MG 卡片部分）。文稿视图（F11）和样式编辑面板（F5）不做界面，交给 AI。验收以 0011 为准。

### 阶段 D：画面能力

范围：变速（F6）、转场（F7）、图片 + 动效（F8）、画中画（F15）、关键帧界面（F16）。

验收：每项功能在界面和 CLI 中都能使用，预览和导出一致。

### 阶段 E：MG 卡片和 AI 编排

范围：小卡 / 半屏卡 / 全屏卡（F12；半屏卡会把主画面移到上半部分）、封面导出（F18）、
`docs/orchestration-guide.md`（给 AI 的编排规则）、`mw guide`。

第一批 MG 模板按内容分类：大数字滚动、图表（柱状 / 折线 / 占比）、文字动效（金句）、
人名条 / 提示条、要点列表、新闻 / 截图卡片、标志出场。每个模板声明适合的卡片尺寸（小卡 / 半屏 / 全屏）和情绪标注。

验收：在 Codex 和 Claude Code 里各说一句话——
「把这段口播剪掉停顿，加顶部标题，字幕用居中黄高亮模板，第二个观点用半屏卡，接上默认片尾，导出封面」——
AI 能自己完成 `inspect → apply → validate → preview --sheet → export`，结果在工作台里可以继续手动调整。

> AI 从阶段 A 开始就能通过 CLI 使用全部已完成的能力，阶段 E 只是补齐编排规则和 MG 模板。

### 待评估（不排进阶段）

- **增量渲染**：只重渲改动过的片段再拼接。叠加层、字幕和转场会跨越剪辑点，分段边界不好定；阶段 D 有转场之后再评估（`docs/decisions/0007`）。
- **备选渲染引擎 HyperFrames**（Apache-2.0）：`ResolvedTimeline` 是渲染层的边界，Remotion 的授权或速度出问题时再评估。
- **MG 卡片分类**参考 Barty-Bart motion-graphics（MIT，只参考分类），和阶段 E 第一批模板一起做。

## 12. 风险

| 风险 | 应对 |
|---|---|
| **范围扩大**：从「轻量编排」变成「轻量剪映」，界面工作量增加约 3–5 倍 | 严格按阶段推进，每个阶段都能独立使用；不追求和剪映的所有细节一致 |
| 时间线交互（拖动、吸附、裁剪）的边界情况很多 | 交互逻辑和吸附计算放在 core 里写纯函数并测试；界面只负责显示 |
| 多路视频同时解码（画中画、转场）导致预览卡顿 | 预览使用 540p 代理文件；导出使用标准化文件 |
| 中文字体在预览和导出里不一致 | 字体显式加载；黄金帧测试 |
| 逐字动画没有真实的发音时间 | `mw align` 本地识音对齐（D27）；没对齐的字幕按字数分配并在界面上标注 |
| 识音对不准（口误、字幕和实际念的不一致、背景音乐） | 编辑距离对齐，认错的同音字按位置对上；匹配率低于 0.8 的句子列出来让人检查；改字幕文字后字数变了就清掉旧的逐字时间 |
| 人和 AI 同时修改工程 | revision 乐观锁 + 轨道锁定 + 界面高亮 AI 的改动 + 撤销 |
| Remotion 渲染速度 | 调整并发数、评估硬件编码；compile 的输出就是以后替换渲染层的边界 |
| 安全区数值不准 | 用三个平台的截图校准；可以按工程修改 |
